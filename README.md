# async_delay — کتابخانه‌ی تاخیرِ غیر-مسدودکننده برای AVR

یک کتابخانه‌ی **header-only** که به میکرو اجازه می‌دهد بدون قفل‌شدن، چند تاخیر هم‌زمان داشته باشد.
سازگار با **ATmega8/16/32** و کامپایلر **CodeVisionAVR**.

> این فایل قرارداد استفاده است — هم برای انسان و هم برای **AI Agent Coder**. قبل از استفاده از
> کتابخانه این را بخوان. برای معماری داخلی به `ARCHITECTURE.md` مراجعه کن.

---

## 🎯 این کتابخانه به چه دردی می‌خورد؟

تفاوت بین دو نگاه به زمان در یک میکرو:

| | `delay_ms(500)` (مسدودکننده) | `async_delay` (غیر-مسدودکننده) |
|---|---|---|
| میکرو در این ۵۰۰ms | **کاملاً قفل است** — هیچ کاری نمی‌کند | **آزاد است** — بقیه‌ی کارها را انجام می‌دهد |
| کار شما | قبل از تاخیر، یا بعد از آن | **همان لحظه** که زمان تمام شد |
| چند تاخیر هم‌زمان | غیرممکن | بله، تا `ASYNC_DELAY_MAX_SLOTS` |
| مناسب برای | راه‌اندازی یک‌باره، مقادیر کوچک | چشمک‌زدن، خواندن سنسور، refresh صفحه‌نمایش، ماشین حالت |

**به‌زبان ساده:** به میکرو می‌گویی «بعد از ۵۰۰ms فلان کار را بکن» و همان لحظه برمی‌گردی به حلقه‌ی اصلی.

---

## ✅ کِی استفاده کنم؟

- **چشمک‌زدن / تایمرها** — چند LED یا عمل با زمان‌های متفاوت، هم‌زمان.
- **Polling منظم سنسورها** — مثلاً هر ۱۰۰ms سنسور را بخوان (اما کار سنگین مثل چاپ LCD را در ISR نکن).
- **refresh صفحه‌نمایش** — صفحه را هر ۲۰۰ms به‌روزرسانی کن، بدون اینکه حلقه قفل شود.
- **ماشین حالت / زنجیره‌ی مراحل** — مرحله‌ی بعدی را با `async_delay_start` زمان‌بندی کن (خود-برنامه‌ریزی، این کتابخانه پشتیبانی می‌کند).
- **دادن «وقت آزاد» به حلقه‌ی اصلی** — حلقه برای کارهای طولانی (محاسبات، UART، LCD) وقت دارد.

## ❌ کِی استفاده نکنم؟

- وقتی به **زمان‌بندی دقیق زیر چند میکروثانیه** نیاز داری (دقت کتابخانه ±1 تیک است؛ مثلاً ±1ms).
- وقتی می‌خواهی **درست وسط یک عملیات متوقف شوی** (مثل پروتکل 1-Wire که timing خیلی دقیق می‌خواهد) — این کتابخانه فقط «انقضا» را اعلام می‌کند، وسط عملیات توقف نمی‌کند.
- وقتی **تاخیر بیشتر از نصفِ بازه‌ی شمارنده** نیاز داری (بخش «محدودیت‌ها» را ببین).
- وقتی **فقط یک تاخیرِ کوتاهِ ساده** می‌خواهی — `delay_ms` ساده‌تر است.

## 🧱 ساختار استفاده (۵ قدم ثابت)

```
1. فلگ‌های پیکربندی را قبل از #include تعریف کن
2. یک تایمر سخت‌افزاری تنظیم کن که هر 1/TICK_HZ ثانیه قطع بزند
3. داخل ISR تایمر → async_delay_tick()
4. در main() یک‌بار → async_delay_init()  و بعد از همه init ها → #asm("sei")
5. از async_delay_start / _periodic / _elapsed / _cancel استفاده کن
```

---

## ⚙️ فلگ‌های پیکربندی (قبل از `#include`)

```c
#define ASYNC_DELAY_TIMER_BITS  16        // عرض شمارنده: 8 / 16 / 32  (پیش‌فرض 16)
#define ASYNC_DELAY_MAX_SLOTS   4         // حداکثر تاخیر هم‌زمان        (پیش‌فرض 4)
#define ASYNC_DELAY_TICK_HZ     1000      // نرخ تیک (اجباری!)  1000 = هر تیک 1ms

// اختیاری — رفتار callback ها (پیش‌فرض 1):
//   1 = اسلات قبل از فراخوانی callback آزاد/ری‌آرم می‌شود (خود-برنامه‌ریزی امن)
//   0 = رفتار قدیمی (callback اول، بعد آزادسازی)
#define ASYNC_DELAY_CALLBACK_RESCHEDULE  1

#include <async_delay.h>
```

| فلگ | پیش‌فرض | اجباری؟ | معنی |
|-----|---------|---------|------|
| `ASYNC_DELAY_TICK_HZ` | — | ✅ بله | نرخ تیک؛ مثال `1000` = هر تیک 1ms |
| `ASYNC_DELAY_TIMER_BITS` | `16` | نه | عرض شمارنده؛ هر چه پهن‌تر، تاخیر بلندتر |
| `ASYNC_DELAY_MAX_SLOTS` | `4` | نه | حداکثر تاخیر هم‌زمان (بیشینه 254) |
| `ASYNC_DELAY_CALLBACK_RESCHEDULE` | `1` | نه | ترتیب اسلات/callback هنگام شلیک |

## 🔌 تنظیم تایمر (مهم‌ترین بخش)

یک تایمر را طوری تنظیم کن که هر `1/TICK_HZ` ثانیه قطع بزند و داخل ISR فقط `async_delay_tick()` صدا زده شود.

**مثال ATmega8 @ 8MHz، تیک 1ms با Timer2 (CTC، پری‌اسکالر /64):**

```c
#define OCR2_1MS  124        // 8MHz/64 = 125kHz → 1ms = 125 تیک → OCR = 124

interrupt [TIM2_COMP] void timer2_comp_isr(void)
{
    async_delay_tick();      // قلب ساعت کتابخانه — فقط همین!
}
```

**فرمول محاسبه‌ی OCR (برای تیک 1ms):**
`OCR = (Clockمیکرو / Prescaler / 1000) - 1`

| Clockمیکرو | Prescaler | Clock تایمر | OCR (برای 1ms) |
|-----------|-----------|-------------|----------------|
| 1 MHz | /8 | 125 kHz | 124 |
| 8 MHz | /64 | 125 kHz | 124 |
| 16 MHz | /64 | 250 kHz | 249 |

> ⚠️ **هر بار که فرکانس را عوض کردی، OCR را دوباره حساب کن.** با OCR اشتباه، تیک 2ms می‌شود و همه‌ی تاخیرها دو برابر می‌شوند.
> ⚠️ در CodeWizardAVR فیلد Compare فقط ۲ رقم دسیمال قبول می‌کند؛ برای 124 بنویس `0x7C`، برای 249 بنویس `0xF9`.

## 🧩 API — چهار تابع + init

| تابع | نقش |
|------|------|
| `async_delay_init()` | همه‌ی اسلات‌ها را آزاد و شمارنده را صفر می‌کند. **یک‌بار، قبل از `sei`** |
| `async_delay_start(duration, cb)` | تاخیر یک‌باره → شماره‌ی اسلات یا `0xFF` اگر جای خالی نباشد |
| `async_delay_start_periodic(duration, cb)` | تاخیر تکرارشونده (خود re-arm می‌شود) → شماره‌ی اسلات |
| `async_delay_elapsed(slot_id)` | برای حالت polling؛ اگر تمام شده `1` برگرداند و اسلات را آزاد کند |
| `async_delay_cancel(slot_id)` | لغو تاخیر و آزادکردن اسلات |

> همه‌ی `duration` ها برحسب **تیک** هستند نه میلی‌ثانیه (مثلاً 500 با TICK_HZ=1000 یعنی 500ms).

## 📝 الگوهای استفاده

### الگوی ۱: چشمک‌زدن LED (دورهای + callback)

```c
unsigned char led_state = 0;

void blink_cb(unsigned char slot_id)   // callback — کوتاه نگه دار!
{
    led_state ^= 1;                    // فقط یک فلگ
}

// در main():
async_delay_start_periodic(500, blink_cb);   // هر 500ms یک‌بار

// در حلقه:
PORTB.0 = led_state;
```

### الگوی ۲: poll کردن (بدون callback)

```c
unsigned char id = async_delay_start(1000, (void *)0);   // بدون callback

while (1)
{
    if (async_delay_elapsed(id))      // 1000 تیک تمام شد؟
    {
        do_something();
        id = async_delay_start(1000, (void *)0);   // دوباره برنامه‌ریزی کن
    }
    // بقیه‌ی کارهای حلقه...
}
```

### الگوی ۳: خود-برنامه‌ریزی (self-reschedule) — مرحله‌بندی کارها

از داخل یک callback، تاخیر بعدی را شروع کن (کتابخانه این را پشتیبانی می‌کند — با فلگ ۱):

```c
unsigned char step = 0;

void step_cb(unsigned char slot_id)
{
    step++;                              // برو مرحله‌ی بعد
    if (step < 3)
        async_delay_start(500, step_cb); // 500ms دیگر، دوباره
    // وقتی step==3، دیگر برنامه‌ریزی نمی‌کنیم → تمام شد
}

// در main():
async_delay_start(500, step_cb);
```

### الگوی ۴: لغو یک تاخیر

```c
unsigned char id = async_delay_start(2000, do_something);
// ... پشیمان شدی:
async_delay_cancel(id);                  // دیگر اجرا نمی‌شود
```

### الگوی ۵: «ری‌استارت» یک تاخیر دوره‌ای از داخل callback خودش

> ⚠️ چون دوره‌ای قبل از callback دوباره arm می‌شود، `start` مجددِ **همان id** یک تایمر دوم می‌سازد.
> الگوی درست:

```c
async_delay_cancel(id);                      // اول قدیمی را لغو کن
id = async_delay_start_periodic(500, cb);    // بعد دوباره شروع کن
```

## 🚫 قوانین طلایی (نقض‌نشدنی)

1. **callback ها باید خیلی کوتاه باشند** — آن‌ها داخل ISR اجرا می‌شوند. فقط فلگ یا پین را عوض کن؛ هرگز `delay_ms`، چاپ LCD، یا کار طولانی نکن.
2. **`async_delay_tick()` فقط از ISR تایمر**، دقیقاً با نرخ `TICK_HZ`.
3. **`async_delay_init()` قبل از `sei`**، یک‌بار.
4. **حداکثر تاخیر مطمئن = نصفِ بازه‌ی شمارنده:**
   - 8 بیت → 128 تیک | 16 بیت → 32767 تیک (~32s در تیک 1ms) | 32 بیت → ~2³¹ تیک
   - بیشتر از این غیرقابل اعتماد است (ابهام سرریز).
5. **خطای کتابخانه حداکثر ±1 تیک** است؛ دقت واقعی را کلاک میکرو تعیین می‌کند (کریستال ~±0.005%، RC داخلی ~±1 تا ±3%).

## 🛠️ نکات برای AI Agent Coder

وقتی از این کتابخانه استفاده می‌کنی:

- **قبل از هر چیز** فلگ‌ها را تعریف کن (قبل از `#include`)، مخصوصاً `ASYNC_DELAY_TICK_HZ`.
- **تایمر را خودت تنظیم کن** — کتابخانه فقط منتظر قطع تایمر است؛ `async_delay_tick()` را داخل ISRِ تایمر صدا بزن.
- **callback ها را با یک `unsigned char slot_id` تعریف کن** — امضای دقیق: `void cb(unsigned char id)`.
- برای **تاخیرِ تکرارشونده** از `_periodic` استفاده کن، نه `_start` داخل یک حلقه.
- برای **لغو در وسط اجرا** از `cancel` استفاده کن.
- برای **زمان‌بندی مرحله‌ای** از الگوی ۳ (خود-برنامه‌ریزی) استفاده کن — نه زنجیره‌ی `delay_ms`.
- `async_delay_start` اگر جای خالی نباشد `0xFF` برمی‌گرداند — بررسی کن.
- به **فرمت OCR** در CodeWizardAVR دقت کن (بیشتر از 99 → هگز).
